# 对话显微镜设计

## 依赖方向

入口 → controller → session → timeline → models。
入口通过 controller 组织后台 prepare，prepare 通过 project_bridge 调用本体。
controller → ui；controller 惰性导入 plot_view。ui 通过注入的回调报告事件，绘图通过注入的范围和消息回调交互。
models、timeline 无 GUI 与 Matplotlib 依赖。桥接层是唯一接触本体源码的位置，接入不依赖词语研究项目。

## 状态与定位

Corpus 保存本体消息对象的只读元组，保持原顺序。TimelineIndex 另建按天时间索引，保留原始下标；二分查找采用 [开始,结束) 语义。Session 管理日期、时段、系统消息显示开关、成员滚动位置和选中消息。

概览按分钟分桶，最多缓存16组总量/系统统计。局部范围仅计算可见数据；系统信息与成员通过独立键分行，避免与真实名称冲突；可见行数按实际画布高度计算，使用滚条访问全部名称，超过2500个点转为密度。密度来自每分钟和名称的记录数量，原文定位仍使用完整消息列表。概览与成员视图分别刷新，分支异常不阻止消息列表和原文查看。

## 运行规则

加载为单后台任务，构建完整新索引后才替换当前状态；失败保留旧数据。Tk和Matplotlib只在主线程操作。拖选事件延迟60毫秒合并，以最新选择为准。主流程保持顺序，纯计算可以用合成数据测试。未设计模型自动解释或话题归因。

## 发布边界

只发布通用源码、依赖、说明。测试、本地数据、配置、输出、截图和日志默认排除。用户提供的项目目录必须可信，运行时导入会执行其顶层代码。父仓库按具体文件名允许通用源码与说明，测试和用户输入文件保持忽略。

## 概览视图

Session 保存 overview_mode，默认 bar。界面通过回调切换条形与积分视图，控制器仅刷新概览，保留选区、成员位置和原文选择。分钟分桶是共同输入；积分算法位于 timeline，按每类当天总量归一化，零分母返回全零。积分图纵轴固定0至1.2，仅标0至1刻度。PlotView只清理自己创建的图形元素，保留拖选控件，缓存分桶和模式以免拖选时重复生成条形。
