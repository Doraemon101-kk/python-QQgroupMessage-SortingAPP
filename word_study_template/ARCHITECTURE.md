# 群聊词语研究模板顶层设计

状态：顶层设计与分阶段实现。接入、配置、命令行、字面匹配算法和报告模块已经实现；可视化已实现月度折线图与研究词词云，详见 IMPLEMENTATION_GUIDE.md。以下包含后续目标，当前可用功能以 README.md 为准。

## 目标与边界

制作独立、可复用、无真实数据的本地研究工具。通过运行时导入现有群聊检索器的 core.py，复用格式读取、时间边界和原始消息定位能力。不修改本体项目，不复制 core.py，不启动桌面界面，不内置任何真实群聊、姓名、路径或分析结论。

“活引用”定义：每次命令运行都从用户指定的本体目录加载当前 core.py；本体变化会在下一次运行生效。同一次运行固定使用同一个模块实例和同一份消息列表，不做运行中的热更新。

首版仅分析一个会话导出，避免跨群拼接上下文。多文件、多会话、模型自动解释、图形界面均不纳入首版。

## 核心设计原则：短主干、独立分支

> 人话版：先把聊天数据读出来、算出统计结果，再把同一份结果分别交给报告、折线图和词云。它们各干各的，谁出错就记下谁的错误，其他功能继续，已经做好的文件照常留下。读取失败会影响后续分析，分析失败会影响依赖统计的图表；可选输出之间不互相拖累。

```text
cli.py → service.py（统一组织任务）
              |
              +→ config.py（配置校验）
              +→ project_bridge.py → 原项目 core.py（加载、筛选）
              +→ study.py → StudyResult（必要前置）
              |
              +→ storage.py（先保存运行清单和 summary.json）
              |
              +→ task_runner.py（每个可选任务单独加载、执行、发布）
                        ├→ report.py       → report.md
                        ├→ monthly_plot.py → monthly_trend.png / svg
                        └→ cloud_plot.py   → word_cloud.png / svg
```

图中分支代表独立依赖，不代表并行执行。当前按顺序执行，便于保持流程清晰。

### 依赖与失败规则

1. 命令行或未来界面通过 service.py 使用完整业务流程，不跨过已经约定的中间服务。
2. 各功能只依赖自己的必要输入。报告不依赖图表，两个图表不依赖对方，也不互相调用。
3. 业务模块不反向导入入口或服务。models.py 的共享数据契约、plot_support.py 的绘图工具以及 storage.py 的基础保存能力允许被相关功能引用；共享前置故障会影响其依赖者。
4. 可选模块在任务执行时才导入。移除报告模块或任一图表模块，其他分支仍能完成。Matplotlib 缺失仅影响绘图与显示。
5. 基础数据读取与分析是必要主干，成功后先保存统计。每个输出任务使用独立临时目录，只发布完整的本任务文件，失败仅清理自己的临时文件。
6. task_status.json 记录成功、失败和具体错误；未选择的任务不执行。进程退出码：0 全部请求成功；2 配置或必要主干失败；3 基础结果已保存、部分可选任务失败。
7. 各任务获得统计结果的独立副本，防止一个任务误改数据后影响其他任务。隔离范围是普通 Python 异常；进程被强制结束、内存耗尽或磁盘整体故障可能影响整次运行。
8. 主流程按顺序展开，参数检查提前报错，复杂职责提取函数，减少条件和异常层层嵌套。

### 文件职责

| 文件 | 职责 |
|---|---|
| cli.py | 参数和命令行提示，只调用服务入口 |
| service.py | 必要前置、基础落盘、输出任务选择与状态汇总 |
| config.py | 配置解析与路径、日期、词组验证 |
| project_bridge.py | 活引用原项目的唯一入口 |
| study.py | 纯统计算法 |
| models.py | 共享数据契约 |
| storage.py | 基础结果、运行清单与状态保存 |
| task_runner.py | 单任务按需加载、输入副本、失败清理和结果发布 |
| report.py | 可选 Markdown 报告；保留旧 write_results 兼容入口 |
| monthly_plot.py / cloud_plot.py | 各自独立的图表任务 |
| plot_support.py | 共有字体选择和单图保存，不组织业务流程 |
| display.py | 可选的已发布图片查看，失败保留文件 |
| visualization.py | 旧 render 接口兼容入口，不在命令行核心依赖链上 |

“有中间层时不跨层”的约束用于既定业务路径；“功能彼此独立”的约束用于可选分支，不通过添加无实际职责的转发层增加调用长度。

## 活引用接口

### 配置来源

本体目录、输入文件、输出目录优先使用命令行明确指定，也可以读取不提交的本地配置。相对路径以配置文件所在目录解析；命令行相对路径以当前工作目录解析。配置错误明确报错，不偷偷搜索磁盘上的其他项目。

### 加载方式

使用 importlib.util.spec_from_file_location 从指定路径导入 core.py。使用带路径摘要的独立模块名，避免与其他库的 core 模块撞名。执行模块前先登记到 sys.modules，以兼容 dataclass 对模块身份的查询；导入失败清理本次登记。

只导入 core.py，不导入 app.py。导入 Python 文件会执行其顶层代码，因此本体路径必须是用户明确指定且信任的项目；不从聊天附件或数据压缩包内寻找可执行模块。

禁止失败后回退到复制的旧版 core.py。缺失或不兼容应在读取数据前说明问题。

### 首版实际复用

- core.load_messages(path)：支持的文件格式、归一化和错误规则均以本体为准。
- core.search(messages, start_date=..., end_date=...)：在原始列表上获得研究范围索引，保持与界面日期语义一致。
- core.context_text(messages, index, radius)：可用于本地人工核对。公开或匿名化逐例输出自行格式化同一组索引，避免其直接带出真实昵称。
- 不使用 core.export_markdown 作为研究报告导出器：它面向检索结果，不能描述出现次数、统计分母等研究口径。

### 最小接口检查

检查 load_messages、search 可调用；检查 search 支持 start_date、end_date 参数。读取后检查消息对象具有 time、text、message_id 字段。检查结果返回结构与跳过条数。错误信息指出缺失接口，不输出聊天正文。

读取前后分别计算 core.py 的 SHA-256；如果运行期间文件改变，停止输出正式结果，要求重新运行。记录本体源码摘要作为复现依据，不将本地绝对目录写入发布报告。

后续本体重构成 Python 包时，只修改 project_bridge，无须修改研究与报告逻辑。

## 共享数据契约

### StudyConfig

字段：terms、start_date、end_date、context_radius、case_sensitive、重复文本统计选项。

研究词默认空列表，实际运行必须填写至少一个非空词。去掉重复词并保留输入顺序。路径参数由运行环境提供，不写入公开示例。默认按字面匹配，不将用户输入当成正则。

### Corpus

字段：messages、eligible_indices、skipped_records、core_sha256、input_sha256。

messages 保留本体返回的对象，不复制为另一套消息类型，不删除或重排；eligible_indices 描述研究范围。上下文使用全量列表，因此允许越过日期边界，但必须标示属于上下文而非统计样本。

### Occurrence

字段：term、message_index、start_offset、end_offset、occurrence_id。

一个词在同一消息中出现三次，产生三个 Occurrence。不同研究词独立匹配；首版同一词采用从左到右、不重叠计数，并在运行清单中记录该规则。命中正文只引用原消息，不在每个用例里复制大段转发文字。

occurrence_id 为本次运行中的可回查编号。message_id 不保证跨会话唯一，不能独自作为全局主键。

忽略大小写模式需要维护原文位置映射：casefold 可能改变字符长度，不能把折叠后偏移直接当原文偏移。首版允许先仅支持区分大小写的字面提取；该选项未实现时必须拒绝请求，不能悄悄给出错误位置。

### StudyResult

包括：研究消息总数、每词出现次数、每词命中消息数、任意词命中消息总数、按月计数和分母、可选的重复正文对照结果、全部 Occurrence。

不把相加的各词消息数当成并集消息数：同一条消息可能包含多个研究词。

## 统计口径

1. 分母为日期等条件筛选后、成功读取的所有记录。当前 Message 没有 type 标记，因此这一分母是“记录数”，不能声称是人类发言数或纯文本消息数。
2. 每千条记录命中率 = 当期含该词的消息数 / 当期研究记录数 * 1000。
3. 出现次数、消息数分别输出，避免长段子重复一个词导致计数混淆。
4. 月份按本体统一后的北京时间分组，月度分子和分母使用同一研究范围。部分月份仅覆盖若干天时，在报告中显示实际起止日期。
5. 原始统计始终保留。重复正文只作为额外对照，定义为正文完全一致；不删除重复记录，不宣称已消除重复导出。
6. 一个会话中的时间相邻消息不必属于同一话题；前后文是辅助证据，不自动推断回复关系。
7. 人工标注默认为空，不自动填情绪、动机或可替换性结论。

## 当前本体接口的能力限制

当前 core.Message 只有 time、sender、aliases、text、message_id。没有稳定发送者 UID、转发标记、系统消息标记和会话 ID。

因此首版不输出可靠的独立使用人数，不将名字当稳定身份，不区分转发者与原作者，不自动排除系统消息。通过“[转发消息]”文字猜测最多只能标记为启发式判断，不可作为默认可靠分类。

需要这些能力时，先由上游提供公开的结构化接口，再由 project_bridge 适配。研究模块不私自复制本体解析器，也不通过用户姓名或 QQ 号补造身份关系。

## 输出设计

- summary.json：机器可读统计及完整口径。
- report.md：基础统计、限制与待研究问题，不嵌入原句。
- concordance.jsonl：可选的本地用例与上下文；可能包含正文中的个人信息，默认不生成。
- annotations.jsonl：可选的本地待标注用例编号与空标签；与上述用例编号关联。
- run_manifest.json：配置、模板版本、核心源码摘要、输入内容摘要、时间、记录数量。默认不含绝对路径、输入文件名和作者身份。

一次运行写入独立目录，输出目录不得等于输入文件或会覆盖本体文件。基础结果先写临时目录并独立发布，之后各输出任务分别执行和保存，失败状态明确记录。已有结果默认不覆盖。

发布模板仅带代码、说明与空配置。data、output、本地配置、日志、截图、压缩包和测试数据均默认排除；敏感内容不会因匿名化发送者而自动从正文消失。

## 第一轮实现与验收

1. 实现桥接加载和接口检查，证明调用的是用户指定的本体，而不是复制代码。
2. 用合成消息实现字面匹配，验证同条多次出现、多词并存、空关键词、日期边界与统计分母。
3. 实现 summary 与 report；没有真实数据时显示缺少配置，不生成虚构研究结论。
4. 实现可选用例与空标注表。检查上下文边界及输出隐私边界。
5. 同一输入和配置产生相同的实质统计；本体修改后下一次运行使用新接口，接口不兼容时明确失败。

当前已实现周边基础设施，用合成消息验证真实本体接口；不导入真实数据，不改动或推送本体项目。去重对照、逐例导出和人工标注仍为后续设计，当前配置不接受未实现的选项。
